# Design

## Authority boundary

`LocalRaidSession` generates one immutable plan before inventory escrow using the
closed map identity and deployment seed. UI and remote peers never choose loot.
The plan is consumed to create authoritative inventory owners and interaction
targets, then remains read-only for audit and inspection.

## Determinism

The plan identity is:

```text
map identity + raid seed + generator version
```

Location selection and each container's contents use separately derived RNG
streams. Adding a content roll to one container therefore does not move optional
containers or reshuffle another container.

## Population layers

- Objective containers: exactly the three authored Supply Run targets. They are
  always active. The first retains the guaranteed Supply Crate objective.
- Optional containers: two candidates selected from six authored sidecar points
  for each map. They do not affect task completion.
- Contents: deterministic weighted rolls packed into the existing 8x6 world-crate
  inventory using an explicit row-major placement algorithm.

## Persistence

Only the closed population descriptor crosses the save boundary:

```text
version, map_id, seed, map_identity, digest
```

The full plan is regenerated by the authoritative host from those inputs. Receipt
validation binds the descriptor to the same deployment request and map descriptor.
No executable data or scene nodes enter the profile.

## Failure behavior

Unknown maps, invalid map identity, malformed candidates, overlapping item
placements, invalid cache data, inventory insertion failure or descriptor mismatch
fail closed. A generated optional point is also checked against the runtime
movement world before interaction registration.

## Presentation

Optional containers use a game-owned visual presenter with no engine physics body.
Authoritative collision remains exclusively in `ZMovementWorld2D`. Tactical map
briefings continue to reveal only task and extraction markers; optional loot is
found in-world.
